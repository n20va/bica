# Бесплатный первый запуск: инструкция

Нужны два файла из проекта:

1. `notebooks/free_colab_pilot.ipynb` — ноутбук с последовательными ячейками.
2. `deliverables/bica_colab_bundle.zip` — код и шесть изображений, меньше нескольких мегабайт.

## Что сделать

1. Открыть https://colab.research.google.com/ в своём Google-аккаунте.
2. Выбрать File → Upload notebook и загрузить `free_colab_pilot.ipynb`.
3. Выбрать Runtime → Change runtime type → T4 GPU. Если бесплатная GPU недоступна, попробовать позже; покупка платного плана не требуется для этой схемы. Ресурсы Colab не гарантированы.
4. Выполнить первую ячейку установки библиотек. Затем выбрать **Среда выполнения → Перезапустить сеанс** (Runtime → Restart session). Продолжить со следующей ячейки проверки GPU, пропустив повторную установку. Перезапуск нужен, чтобы загруженные в память модули Pillow соответствовали установленной версии.
5. Подключить Google Drive в предложенном интерфейсе: туда будут записываться результаты в `My Drive/BICA_free`.
6. Когда появится выбор файла, загрузить **ZIP-архив целиком**, не распаковывая его вручную.
7. Дождаться загрузки модели. Веса загружаются в облачную среду и не занимают место на Mac.
8. Выполнить проверку на одном изображении. При ошибке не запускать большой проход; сохранить текст ошибки и `trace.jsonl` из папки `probe_v2`.
9. После успешной проверки выполнить сравнение на шести изображениях. Появится прогресс `1/24`, `2/24` и так далее.
10. Скачать архив результатов последней ячейкой. Он также содержит пакет для независимой разметки ответов.

Никаких API-ключей, карты или покупки вычислений этот ноутбук не требует. Включать платные ресурсы не нужно. Бесплатные квоты зависят от Google; ноутбук не обходит ограничения и не поддерживает искусственное удержание сессии.

## Что сохранится

- Точные версия модели, ревизия весов, параметры обработки картинок, библиотеки и GPU.
- Запросы, сырые ответы, время и использование токенов.
- Отдельный JSON каждого завершённого случая, включая ошибки.
- Таблица технических статусов — это ещё не точность распознавания.
- Файлы для независимой оценки правильности интерпретаций и признаков.

При обрыве заново подключить GPU, Drive и тот же архив. Повторный вызов `run_pilot` пропускает сохранённые случаи. Незавершённый случай может повторить часть обращений, поэтому общий счётчик включает прерванные попытки. Если исчерпан лимит, продолжать можно после явного увеличения `max_calls` в ячейке; платных запросов это не создаёт.

Если изменились код, промпты, модель, Python или GPU, проверка конфигурации может запретить продолжение. Сохранить старый эксперимент и использовать новое имя папки; не смешивать разные условия в одной серии.

## После первого запуска

Разобрать реальные ответы и ошибки формата, проверить разметку, добавить отрицательные изображения и истинные/ложные подсказки. На шести классических иллюзиях нельзя подтвердить научную гипотезу. Это первый рабочий шаг к результатам, не вся курсовая.

Архив содержит опубликованные ответы AmbiBench отдельно от входных данных. Они не являются готовой независимой человеческой оценкой. Нужны два оценщика; ответы моделей и их признаки проверяются по изображению. Не менять `review_status` на `adjudicated` до проверки.

## Проверено здесь и что ещё не проверено

При первом запуске у пользователя обнаружен `ImportError: cannot import name '_Ink' from 'PIL._typing'`. Вероятная причина — смешение загруженной и установленной версий Pillow после `%pip install`. В ноутбук добавлены явный шаг перезапуска сеанса и ранняя проверка импорта Pillow. После перезапуска пользователь подтвердил скриншотом загрузку Qwen на T4 и прислал первый реальный ответ.

Первый ответ содержал корректный JSON внутри Markdown-блока и `cue_verdict: supported` при отсутствии подсказки. В версии обработки v2 допускается ровно один внешний блок JSON; произвольный текст, обрыв JSON и неверная структура по-прежнему вызывают ошибку. Для нейтральных случаев поле оценки подсказки помечается `not_applicable`. Интерпретации, признаки и исходная история диалога не меняются. Сырой ответ и каждое преобразование сохраняются в журнале. Эти правила одинаковы во всех четырёх режимах; при наличии подсказки её вердикт не исправляется.

Пройдены 25 тестов Python, включая проверку такого ответа во всех режимах, сохранение исходного текста и отказ от исправления повреждённого JSON. Ноутбук создан и прочитан через IDE. Полный GPU-пилот после исправления ещё не подтверждён; качество распознавания пока не оценено.

## Обновление уже открытой сессии после ошибки JSON

Не перезапускайте сеанс и не загружайте модель заново. Повторите ячейку загрузки ZIP, выбрав обновлённый `deliverables/bica_colab_bundle.zip`. Затем выполните новую ячейку:

```python
import importlib
import illusion_agent.core as core
import illusion_agent.colab as colab
importlib.invalidate_caches()
importlib.reload(core)
importlib.reload(colab)
from illusion_agent.colab import run_pilot

probe = run_pilot(client, MANIFEST, SAVE / 'probe_v2',
                  modes=('direct',), limit=1, max_calls=2)
print(probe)
```

Для продолжения нужны `completed_cases: 1` и `errors: 0`. Старый `probe_v1` не удаляйте: он сохраняет исходную ошибку. В обновлённом ноутбуке основной запуск и оценка используют `pilot_v2` и `reviewer_a_v2`. Если продолжаете в старом ноутбуке, замените все `pilot_v1` на `pilot_v2`, а `reviewer_a_v1` на `reviewer_a_v2` в следующих ячейках.

Источники: [модель Qwen2.5-VL-3B](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct), [AmbiBench](https://huggingface.co/datasets/BLNL/AmbiBench), [правила Colab](https://research.google.com/colaboratory/faq.html).
