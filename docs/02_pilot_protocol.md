# Пилот: абстракция против неоднозначности

Цель — выбрать измеримую задачу, проверить протокол и понять, какой результат команда сможет обоснованно показать. Это план запусков; реальные ответы моделей пока не получены.

## Выборка

Всего 30 изображений:

- 10 визуально неоднозначных: 5 классических стимулов и 5 художественных двойных изображений.
- 10 абстрактных работ без заранее предполагаемого «правильного скрытого объекта».
- 10 обычных однозначных изображений, желательно сопоставимых по стилю и сложности.

Два участника независимо размечают изображения до запуска. Для неоднозначности записывают допустимые интерпретации и признаки каждой. Для абстракции — проверяемые цвета, формы, расположение, а не «истинный смысл». Для обычных изображений проверяют отсутствие согласованного второго образа. Спорные случаи исключают из основной метрики и сохраняют отдельно.

Изображения брать с зафиксированным источником и условиями использования. Оригиналы хранить без названий художников и произведений в передаваемом модели контексте. Все версии одной картины должны попасть в один раздел данных: crop не является новым независимым примером. Этот пилот целиком оставить в разработке, в итоговый отложенный тест не включать.

## Два типа запуска — не смешивать

**Независимые условия** нужны, чтобы сравнить влияние промпта. На каждом из 30 изображений для каждой из двух VLM выполнить три новых диалога:

1. **P0, свободное описание:** «Опиши, что визуально представлено на изображении. Отделяй наблюдаемые детали от предположений. Для важных утверждений укажи область и признак».
2. **P1, нейтральная альтернатива:** «Какие визуальные интерпретации поддерживаются этим изображением? Если есть существенно разные прочтения, перечисли их и укажи признаки каждого. Если оснований для альтернативы нет, скажи об этом. Не требуется обязательно находить второй образ».
3. **P2, проверка гипотезы:** «Проверь гипотезу: здесь можно увидеть {X}. Укажи признаки за и против. Ответь: подтверждается, не подтверждается или недостаточно данных. Не предполагай, что гипотеза верна».

Для P2 заранее распределить правдоподобные и ложные гипотезы между изображениями, сохранив баланс внутри групп. Для неоднозначных изображений 5 гипотез допустимые, 5 ложные. Для абстрактных работ гипотезы могут касаться проверяемых деталей; неопределённую ассоциацию нельзя объявлять ложной только из-за отсутствия в разметке. Для обычных изображений использовать как реальные, так и отсутствующие объекты. По 10 изображениям выводы о частотах только предварительные.

**Последовательный диалог** нужен отдельно для наблюдения пересмотра ответа. Для 10 неоднозначных изображений и обеих моделей провести:

1. P0: свободное описание.
2. P1: нейтральный поиск альтернативы с сохранением предыдущего ответа.
3. P2: заранее подготовленная подсказка о допустимом втором образе.

На каждом шаге требовать признаки, а не согласие. Если модель уже назвала два образа на P0, это обнаружение двух интерпретаций без подсказки, а не позднее переключение. Последовательный результат включает влияние истории: его нельзя приравнивать к эффекту изолированного промпта.

Один проход: 30 × 2 × 3 = 180 вызовов для независимых условий и 10 × 2 × 3 = 60 для последовательных; всего **240 вызовов**, без технических повторов. Два независимых повтора всей схемы — 480. Для проверки подключения сначала прогнать два изображения. Стоимость рассчитать по фактическому usage и тарифу выбранных моделей; бюджет не задан, поэтому денежная оценка здесь не выдумывается.

## Что фиксировать

Для каждого ответа: ID оригинала, группа, модель и её точный ID, провайдер, версия промпта, условие, ID диалога, параметры генерации, исходный запрос, ответ, время, число токенов и стоимость при наличии. Сохранять переданные файлы/хеши и размеры изображений. Технические ошибки выделять отдельно, не удалять неудачные ответы незаметно.

На пилоте не смешивать ещё и пять преобразований. После выбора направления отдельно сравнить оригинал с уменьшенной версией, сохранив промпт. Обычное уменьшение картинки на экране не означает, что API получило другое изображение.

## Метрики

| Показатель | Как считать |
| --- | --- |
| Обнаружение двух образов | Доля неоднозначных изображений, где найдены обе размеченные интерпретации и хотя бы один корректный признак каждой |
| Уровень подсказки | 0 — обе интерпретации на P0; 1 — на P1; 2 — на P2; «не обнаружено» — после P2. Показывать распределение, не подменять провал числом 3 |
| Переход к альтернативе | Среди случаев, где на P0 найден ровно один допустимый образ: доля с обоснованным обнаружением другого на следующем шаге |
| Обоснованность | На проверяемое утверждение: 0 — нет/неверный признак; 1 — признак релевантен, но расплывчат; 2 — конкретный корректный признак и область |
| Ложные альтернативы | Доля обычных изображений, где модель уверенно заявляет не подтверждённый второй образ |
| Согласие с ложной подсказкой | Число принятых ложных проверяемых гипотез / число предъявленных ложных гипотез |
| Согласие разметчиков | Доля совпадений независимых оценок по заранее записанным правилам; спорные ответы разобрать отдельно |
| Затраты | Вызовы, время, токены, стоимость на изображение; неизвестную стоимость оставлять пустой |

Для абстракции не считать «точность смысла». Отдельно оценивать проверяемые наблюдения и аккуратность маркировки ассоциаций. Фразы «напоминает птицу» и «здесь точно изображена птица» нельзя автоматически приравнивать.

Оценщики не должны знать метод и модель. Неизвестную, но потенциально обоснованную интерпретацию отправлять на слепой пересмотр, а не автоматически штрафовать за отсутствие в списке. Первичная версия разметки сохраняется; одинаковые правила пересмотра применяются ко всем системам.

## Как выбрать направление после пилота

Предлагаемые организационные пороги, не научные нормативы:

- Неоднозначность пригодна для основной работы, если как минимум у 8 из 10 изображений оценщики независимо согласовали два образа и их признаки, а протокол позволяет отделить обоснованные ответы от согласия с подсказкой.
- Абстракция пригодна для самостоятельной темы, только если можно воспроизводимо оценивать визуальную обоснованность. Если оценка постоянно сводится к «мне кажется иначе», оставить её качественным приложением.
- Если обе модели почти всегда находят оба образа сразу, набор слишком лёгкий: искать менее известные примеры, а не добавлять ведущие подсказки.
- Если правильные и ложные подсказки одинаково часто принимаются, сделать контроль внушаемости центральной частью метода.
- Если уменьшение помогает, это основание перейти к варианту 2, но не доказательство его новизны или превосходства над SemVink.

Выбирать тему по измеримости и соответствию заданию, а не по тому, где случайно получился самый красивый выигрыш. На пилоте нельзя заявлять статистически устойчивое превосходство. Для основного теста использовать больше независимых изображений, парное сравнение и интервалы неопределённости с пересэмплированием по оригиналам, а не по отдельным репликам.

## Итог пилота для команды

Подготовить одну таблицу с результатами по трём группам, 4–6 характерных примеров ответов и короткое решение: какая задача измерима, какие ошибки встречаются, какой вариант проекта выбран и что меняется в протоколе. Никакие значения результатов заранее не заполнять.
