# Научная постановка после проверки литературы

Дата проверки: 10.11.2026. Этот документ уточняет ранние планы 01–03. Статус: исследовательский прототип, результативность ещё не измерена.

## Решение

Начинаем вариант 1: **контроль конкурирующих интерпретаций при истинных и ложных контекстных подсказках**. Абстрактное искусство остаётся разведочным сравнением; адаптивные визуальные инструменты — возможным следующим этапом.

Научная ценность: отделить полезную гибкость интерпретаций от внушаемости. Метод может находить больше альтернатив просто потому, что соглашается с любой подсказкой. Поэтому прирост обнаружения второго образа оценивается вместе с ложными альтернативами, принятием неверных подсказок и техническими сбоями.

**Проверяемый вклад:** экспериментально установить, даёт ли явное сохранение альтернатив и отдельный аудит их визуальных оснований преимущество над обычной повторной проверкой при одинаковом лимите обращений к одной VLM. Новизна предполагается в конкретном сравнительном протоколе и организации контроля; мировое первенство не установлено.

Это целевой обзор ближайших работ, не систематический обзор всей литературы. Проверены первичные страницы/публикации; подробное воспроизведение методов ещё впереди. По этим источникам нельзя обещать, что никто ранее не соединял подобные компоненты.

Новый практический факт: найден [публичный релиз AmbiBench](https://huggingface.co/datasets/BLNL/AmbiBench), несмотря на недоступность PDF OpenReview через браузерную проверку. Поэтому статус «доступ к данным не подтверждён» из первоначального плана устарел. Числа примеров в разных версиях статьи и релиза могут различаться; использовать фактическую ревизию данных.

## Гипотезы и условия опровержения

H1. Полный агент чаще обнаруживает две допустимые интерпретации, чем обычная повторная проверка с теми же тремя вызовами, без практически существенного роста ложных альтернатив.

H2. Отдельный аудит признаков уменьшает принятие ложной подсказки по сравнению с сохранением гипотез без специального аудита. При этом нужно проверить, не исчезает ли полезное обнаружение второго образа.

H3. Выигрыш воспроизводится на второй базовой VLM. Если он наблюдается только на одной, вывод ограничивается этой моделью.

Если полный агент лишь становится осторожнее и перестаёт распознавать допустимые образы, H1 не подтверждается. Если он работает не лучше повторной проверки, нельзя приписывать эффект новой архитектуре. Нулевой или отрицательный результат полезен как проверка границ подхода, но не как доказательство превосходства.

## Протокол v0.1

Четыре режима уже реализованы:

- `direct`: один запрос; минимальный ориентир.
- `repeat`: описание → повторная проверка → повторная проверка; три вызова.
- `hypotheses`: описание → поиск и сохранение альтернатив → сведение ответа; три вызова.
- `evidence`: описание → поиск и сохранение альтернатив → проверка признаков и контраргументов; три вызова.

Все режимы используют одинаковую схему ответа и получают одно и то же изображение. Общая инструкция уже просит указывать признаки: различие состоит в специальном этапе проверки, а не в наличии поля evidence. Отключение этого этапа — частичная абляция; режим `hypotheses` может спонтанно проверять признаки. Это ограничение нужно указать в отчёте.

В v0.1 память гипотез представлена структурированными ответами в истории одного диалога. Контроллер — фиксированная последовательность этапов; адаптивный выбор действий и инструментальный просмотр ещё не реализованы. Проверка JSON контролирует форму ответа, а не истинность указанных признаков.

Для каждого изображения нужны независимые диалоги в трёх условиях: без подсказки, с верной гипотезой, с правдоподобной ложной гипотезой. Одинаковые условия предъявлять всем методам; порядок перемешивать. В метаданных для модели нет признака «верная/ложная» и названий исходных файлов. Не смешивать независимые условия с последовательной лестницей подсказок раннего плана.

На 30 изображениях, при трёх условиях, четырёх режимах и одном повторе: **30 × 3 × (1 + 3 + 3 + 3) = 900 вызовов на одну VLM**, 1 800 на две. Это предложение полного пилота v0.1, а не уже выполненный запуск. Начать с 2–6 изображений для проверки инфраструктуры. Дальнейший размер основного теста выбрать после оценки вариативности и ресурсов.

Нейтральный режим оценивает самостоятельное обнаружение. Верная подсказка — способность проверить предложенный образ. Ложная — устойчивость к внушению. Эти результаты показывать раздельно. Для абстрактных работ ложность утверждения допустимо размечать только для проверяемой детали; свободную ассоциацию нельзя объявлять ложной по отсутствию в списке.

## Оценка

Два человека независимо проверяют допустимость интерпретаций и визуальные признаки. Затем разрешают разногласия, сохраняя исходные оценки. Ответы предъявляются без названия модели и метода; по стилю ответа слепота может быть неполной.

Основные показатели:

1. Доля неоднозначных изображений с двумя правильными интерпретациями и корректными признаками.
2. Доля обычных изображений с выдуманной альтернативой.
3. Правильное принятие/отклонение подсказки, отдельно для истинных и ложных.
4. Визуальная обоснованность, технические ошибки, вызовы, время и usage.

Показывать совместно полноту обнаружения и ложные срабатывания; не сводить их произвольной формулой в один «индекс интеллекта». Перед основным тестом зафиксировать допустимый рост ложных срабатываний и минимальный интересующий выигрыш. До фиксации этих порогов и достаточной выборки не заявлять подтверждение H1.

Основные сравнения парные по исходным изображениям. Повторные ответы и варианты одной картинки не являются независимыми примерами. Для итогового анализа планируется парный bootstrap по оригиналам с 95% интервалами; в v0.1 реализованы только описательные доли, без проверки значимости. Технические ошибки остаются в знаменателях показателей успеха и отдельно показываются рядом с ложными срабатываниями.

## Соответствие заданию преподавателя

Прототип закрывает начало разработки собственного агента и экспериментального стенда. Четыре собственных режима **не заменяют двух опубликованных SOTA-агентов**. Для следующего этапа остаются воспроизведение/адаптация Visual Sketchpad и Tool-Guided VLMs; SemVink — дополнительное профильное сравнение. Никаких результатов этих методов пока нет.

Внешняя оценка: AmbiBench как основной профильный кандидат, IllusionBench как проверка иллюзий и отрицательных примеров; HC-Bench как резерв/расширение. Сохранить исходные вопросы и правила оценки при официальном сравнении. Нынешние шесть изображений AmbiBench с нашим нейтральным запросом — отладочная выборка, **не официальный результат бенчмарка**.
