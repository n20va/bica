# BICA: контроль интерпретаций визуальных иллюзий

Исследовательский вопрос: помогает ли сохранение альтернативных интерпретаций и отдельная проверка признаков находить второй образ, не повышая внушаемость модели?

Научная постановка и ближайшие работы: [docs/04_research_contribution.md](docs/04_research_contribution.md). Ранние варианты темы: [docs/01_project_plans.md](docs/01_project_plans.md).

## Текущее состояние

Реализованы четыре режима, независимые условия с подсказками, журналирование запросов/ответов, контроль числа вызовов, проверка формата, экспорт для слепой человеческой оценки и подсчёт описательных метрик. Работают без сторонних Python-пакетов, Python 3.11+.

Подготовлены шесть реальных изображений AmbiBench для отладки. Их разметка получена от авторов датасета и ещё требует проверки двумя людьми. Пока для них включён только нейтральный запрос. Отрицательные примеры, абстракция и проверенные подсказки для полноценного пилота ещё не подготовлены.

**Реальных VLM-экспериментов пока нет.** `mock` возвращает пустой ответ с неопределённостью и проверяет только инфраструктуру. Экспорт и оценка научных метрик для mock запрещены программно. Два внешних агентных метода ещё не подключены; наши режимы не называются SOTA.

## Быстрый запуск из PyCharm или терминала

Скрипт получает текущую ревизию, скачивает только выбранные изображения, записывает хеши и ссылки в `provenance.json`. Для повторения точно той же выборки передать `--revision` из этого файла. Публичный релиз: [AmbiBench](https://huggingface.co/datasets/BLNL/AmbiBench). Шесть выбранных примеров предназначены только для разработки; не возвращать их в отложенный тест.

## Реальная локальная модель, когда появится доступ

Есть адаптер локального [Ollama Chat API](https://docs.ollama.com/api/chat). Он ещё не проверен на живой VLM: проверен только формат HTTP-запроса с подменённым транспортом. Требуется установленная модель с поддержкой изображений. Модели автоматически не скачиваются.

```bash
.venv/bin/python -m illusion_agent run \
  --manifest data/ambibench_debug/manifest.jsonl \
  --provider ollama --model YOUR_INSTALLED_VISION_MODEL \
  --modes direct --max-calls 6 --output runs/first_real_run
```

Затем заменить `--modes direct` на `--modes direct,repeat,hypotheses,evidence` и увеличить лимит до 60. Зафиксировать версию Ollama, точный digest модели, оборудование и настройки перед исследовательскими запусками: эти сведения пока не считываются автоматически. Адаптер облачного API будет выбран после выбора сервиса; универсальная поддержка всех провайдеров не заявляется.

## Данные и защита от утечки ответов

`manifest.jsonl` содержит только `id`, `original_id`, `image`, `sha256`, `split`, `cues`. В `cues` разрешены только ID условия и текст гипотезы; её истинность хранится отдельно. Исходные названия файлов, ответы, категория и split модели не отправляются.

Эталоны лежат в `annotations.jsonl`; runner их не читает. Изображения кодируются в base64; в журнале текст запроса сохраняется полностью, а изображение обозначается хешем и копируется в папку запуска. Между случаями история сбрасывается. Один оригинал и один и тот же хеш изображения не могут встречаться в разных split. Семантически близкие перерисовки должен дополнительно объединять разметчик через `original_id`.

Строгая схема JSON едина для всех режимов. Неверный формат — техническая ошибка, без скрытых повторов или исправления ответов. Случай останавливается, сырой ответ сохраняется; остальные случаи продолжаются. При ошибках команда возвращает ненулевой код.

## Независимая оценка

После реального запуска:

```bash
.venv/bin/python -m illusion_agent export-review \
  --run runs/first_real_run --manifest data/ambibench_debug/manifest.jsonl \
  --output reviews/reviewer_a
```

Оценщик получает изображения, `packets.json` и пустой `ratings.csv`, без названий методов и моделей. Сопоставление ID сохраняется отдельно в папке запуска; его не давать оценщику. Для второго оценщика сделать другой экспорт с другим `--seed`. Оценки затем сопоставить по закрытой таблице и разрешить разногласия. Не объединять строки разных экспортов по номеру без mapping.

Смысл полей в `ratings.csv`:

- `both_valid`: 1, если названы обе допустимые интерпретации с правильными признаками, иначе 0; только для группы `ambiguous`.
- `false_alternative`: 1 при неподтверждённой альтернативе, иначе 0; только для `ordinary`.
- `cue_correct`: 1, если истинная подсказка обоснованно принята или ложная обоснованно отвергнута; неопределённость даёт 0. Без подсказки — `NA`.
- `grounded`: 1, если есть хотя бы одна поддержанная интерпретация и все заявленные как поддержанные интерпретации имеют корректные конкретные признаки; иначе 0.
- Для неприменимого поля и технической ошибки писать `NA`, не оставлять пустым. При ошибке метрики успеха получают 0 при агрегации; частота ложных альтернатив вычисляется среди успешно завершённых ответов, с отдельным числом сбоев.

После согласования эталонов заменить их `review_status` на `adjudicated`; не делать это только ради обхода проверки. `group`: `ambiguous`, `ordinary` или `abstract`; тип каждого cue: `neutral`, `supported` или `misleading`.

```bash
.venv/bin/python -m illusion_agent score \
  --run runs/first_real_run --mapping runs/first_real_run/reviewer_a_mapping.json \
  --ratings reviews/reviewer_a/ratings_consensus.csv \
  --annotations data/ambibench_debug/annotations.jsonl --output reports/pilot_metrics.json
```

Создать папку `reports` заранее. Считаются отдельные доли по режиму, группе и типу подсказки с явными знаменателями. Пропуски и дубликаты отклоняются. Доверительные интервалы и парные тесты ещё не реализованы; сравнивать число повторных ответов с числом независимых изображений нельзя.
